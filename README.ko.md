## 빠른 시작

### 1. 스킬을 설치합니다.

[skills.sh](https://skills.sh/) CLI로 설치합니다. 스킬 실행에는 Node.js 22.18.0 이상이 필요합니다.

```sh
npx skills add https://github.com/choegyumin/architecture-companion --skill architecture-companion
```

### 2. 다이어그램을 생성하고, 댓글로 질문하고, 작업을 지시하세요.

다이어그램은 코드를 근거로 생성되며, 그림으로 코드를 이해할 수 있습니다. 또한, 다이어그램에 바로 피드백을 남겨 에이전트에 대한 후속 요청을 전달할 수 있습니다.

```text
❯ /architecture-companion 장바구니 페이지 컴포넌트의 렌더 트리를 그려줘.

● 정적 분석을 통해 CartPage를 루트로 하는 컴포넌트 구조를 다이어그램으로 만들었습니다.

  아티팩트 URL: http://127.0.0.1:4317
  아티팩트 이름: Code Design > Cart Page Component Structure

❯ 댓글 확인하고 답변해줘.

● 아티팩트에서 댓글 2건을 확인했습니다.

  1. CartItemList: "수량 변경 핸들러가 몇 단계를 거쳐 전달되지?
     onQuantityChange가 CartPage → CartItemList → CartItem로 2단계 전달됩니다 (CartPage.tsx:24).
  2. OrderSummary: "쿠폰 할인이 결제 총액을 대상으로 계산되나?"
     쿠폰 할인은 배송비를 제외한 상품 금액에만 적용되며, 배송비는 '배송비 무료 쿠폰'으로 별도 처리됩니다 (domain/cart.tsx:15, components/OrderSummary.tsx:25).

❯ 새 댓글 확인하고 작업 시작해.

● 새 댓글을 확인했습니다.

  1. CartPage: "items.length === 0 분기의 인라인 마크업을 Empty 컴포넌트로 교체해."
  2. CartItemList: "수량 변경은 계속 CartPage가 담당하고, CartItem은 CartPage에서 조립해 children으로 넘겨줘. CartItemList는 레이아웃만 담당해야 해."
  3. OrderSummary: "할인 내역에서 배송비 면제를 상품 할인과 별도 항목으로 분리해 표기해줘."

  작업을 시작합니다.
```

### 3. 다음 작업에서도 이어서 사용하기

다이어그램은 아티팩트 형태로 프로젝트의 `.architecture-companion/`에 저장됩니다. 저장된 아티팩트를 다시 열어 검토하거나, 소스가 바뀐 뒤 같은 목적과 기준으로 갱신하도록 요청할 수 있습니다.

```text
❯ /architecture-companion 아티팩트를 현재 소스코드 기준으로 갱신해줘.
```

커밋을 원하지 않는다면 `.gitignore`에 `.architecture-companion/`를 추가하세요.

## 왜 Architecture Companion인가

코드 변경을 에이전트에게 맡긴 뒤에도, 사람에게는 이해와 판단, 책임이 남습니다. 구현이 요구사항을 충족하는지, blah blah. 구현 속도의 증가는 인간의 검증 비용 증가 blah blah. 검증 대상 자체를 좁히는 것도 효과적인 방법이지만 (AI에게 위임), 여전히 검증해야 하는 지점이 있다면 검증 방법을 바꾸는 것도 효과적이라 생각했습니다.

다이어그램은 주로 이해를 위한 도구였습니다. 사람 사이의 협업에서 쓰였으며, 이제는 AI의 응답을 이해하는 데에도 쓰입니다.

에이전트나 기존 도구로도 다이어그램 자체는 얻을 수 있습니다. Architecture Companion이 채우려는 간극은 네 가지입니다.

- **에이전트가 그리는 그림은 해석 결과입니다.** 코딩 에이전트에 다이어그램을 요청하면 모델이 코드를 읽고 떠올린 구조를 그립니다. 같은 코드로 다시 요청하면 다른 그림이 나올 수 있고, 그려진 관계가 어느 소스에서 왔는지 확인할 길이 없습니다. Architecture Companion은 정적 분석 결과를 근거로 다이어그램을 생성합니다.
- **다이어그램 단위 추상화는 맥락을 끊습니다.** C4 모델처럼 다이어그램마다 한 계층 레벨씩 보여주는 방식에서는, 상위 레벨을 표현하면 내부 요소 사이의 관계를 볼 수 없고, 하위 레벨만 표현하면 상위 형제 요소와의 관계를 볼 수 없습니다. Architecture Companion은 다이어그램을 추상화하는 대신, 하나의 다이어그램 안에서 상호작용으로 표현할 정보를 바꿔 인지부하를 줄입니다.
- **범용 도구는 의존 그래프에 머뭅니다.** 코드를 분석해 그리는 도구도 대부분 파일·모듈의 의존과 참조 관계까지만 표현합니다. Architecture Companion은 컴포넌트 렌더 트리처럼 질문의 종류에 맞는 분석과 시각적 표현을 제공합니다.
- **기존 다이어그램은 일회성입니다.** 다이어그램은 주로 이해를 위한 도구였습니다. 사람 사이의 협업에서 쓰였으며, 이제는 AI의 응답을 이해하는 데에도 쓰입니다. Architecture Companion은 Annotation 등의 기능으로 이해를 넘어 AI와의 협업을 지원합니다.

다이어그램은 그림 하나에 모든 정보를 담으면 복잡해지고, 단순화하면 무용지물이 됩니다. 그래서 기존 다이어그램 도구는 이해를 돕는 데 머뭅니다. 물론 목적에 충실하여 이해에 큰 도움을 주지만, 스파게티 코드를 정리하는 작업에는 직접적인 도움을 주지 못합니다. Architecture Companion은 이 문제를 해결하고 AI가 생성한 코드를 핸들링하기 위해 설계되었습니다.

그러나 Architecture Companion은 설계와 구조를 표현하는 데에 집중하고, 코드 한줄 한줄을 그림으로 옮기는 데에는 관심을 두지 않습니다. 그 수준에서는 코드를 직접 읽거나 에이전트에게 물어보는 쪽이 대체로 더 효율적이고, 아티팩트에 모두 기록하면 작은 변경에도 갱신하느라 관리 비용이 폭증하기 때문입니다. 그림은 어디를 볼지 알려 주고, 그 안의 내용은 코드와 에이전트가 답합니다. Architecture Companion은 이 역할 분담 위에서 동작합니다.
