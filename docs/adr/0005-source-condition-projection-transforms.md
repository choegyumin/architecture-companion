# 소스 조건식 투영: 그대로 쓰지 못하는 식의 변환 분류

컴포넌트 구조 다이어그램의 컨트롤 모델(ADR 0001)은 소스의 게이트 식을 컨트롤로 옮기지만, 모든 식을 텍스트 그대로 옮길 수는 없다. `spike/owner-controls-and-route-inference`에서 동일 판별식의 if 체인(`state.status === "loading"` / `state.status === "error"`)이 별개 결정 노드로 투영되어, 함께 성립할 수 없는 두 스위치가 동시에 켜지는 결함(463b132로 응급 정산)이 확인됐다. 이 ADR은 원천 식이 변환 없이는 컨트롤 모델에 들어갈 수 없는 경우를 6류로 분류해 기록하고, ADR 0001의 일부 결정(케이스 라벨 원문 유지, 복합식 미분해)을 갱신한다.

## 변환 분류

1. **동일 판별식, 다른 비교값** — 주어가 같고 비교값만 다른 식들(등식·부등식 연쇄, `switch`, else-if). 그대로 두면 각각 노드가 되어 배타가 구조에서 사라진다. 변환: 판별식을 분기 컨트롤 1개로 병합하고 비교값마다 케이스를 둔다. 라벨도 유도한다 — 분기 라벨은 주어, 케이스 라벨은 비교값. 원문 표현식은 라벨로 쓰지 않는다. 케이스 라벨의 인용부호는 유지한다: 문자열 리터럴의 인용부호가 타입을 구분하고(`"1"` ↔ `1`) 케이스 id 충돌을 막는다 — 초기 구현의 따옴표 제거를 반전한다. 인용부호 스타일은 이중 인용부호로 정규화해 `'dark'`와 `"dark"`가 여전히 한 케이스로 접히게 하고, 숫자·합성 `otherwise`·switch의 `default`는 그대로 둔다.
2. **식이 없는 경로** — `else`, `default`, early-return fall-through. 가져올 식 자체가 없으므로 나머지(여집합) 케이스를 합성한다. 1류의 전제다.
3. **부정형** — `!X`, 이중부정, `!(A || B)`. 양형으로 정규화(이중부정 제거, 드모르건)하고 부정은 규칙 언어의 값 차이로 표현한다. 소비자(클라이언트)가 라벨 텍스트를 파싱해 극성을 판정하는 일은 없앴다 — 라벨은 이중부정을 걷어내 유도하고(`!(!x)` → `x`, 괄호는 우선순위가 요구할 때만), 불린 주제 분기는 `polarityPair` 표식을 스키마로 실어 스위치 여부를 데이터로 알린다.
4. **복합식** — `A && B`, `A || B`. 순수 결합·분리는 규칙 언어(AND=Rule, OR=Ruleset)로 분해해 컨트롤 단위 조작·재사용을 가능하게 한다. 분해 불가(함수 호출, getter, 부수효과)는 원자 조건부로 보존한다. 구현 범위: 게이트 조건이 `&&`·`||`·`!`·괄호의 순수 조합이면 DNF로 전개해 원자 피연산자마다 컨트롤을 둔다 — 조건 위치(if·삼항)가 주된 갭이었다(JSX `&&` 체인은 이미 분해됨). 원자 불린 게이트는 기존 true/false 분기·on/off 조건부를 유지하므로 스위치 표현이 사라지지 않는다. 부정은 절마다 뒤집힌 리터럴 하나를 고르는 곱으로 전개한다 — 순수 분리는 폭 무관 AND 규칙 1개(`¬(A∨B∨C∨D)` = `¬A∧¬B∧¬C∧¬D`), 절 내 다중 리터럴은 곱이 되고 상한 초과 시 통짜 게이트로 되돌린다. 렌더하지 않는 팔(`… ? <X/> : null`의 부정 팔)의 전개는 요구하지 않는다. `left || right`·`left ?? right`처럼 양쪽 피연산자가 각자 렌더를 가질 때는 규칙 분해 대신 분기(케이스 left/right)로 모델링하되, 결정 주제는 어차피 왼쪽 피연산자의 진위(`??`는 null 여부)다 — 2값 주제이므로 `polarityPair` 스위치로 표시한다. 케이스 라벨에 대체원의 신원을 싣지 않는다: 오른쪽 피연산자는 자체 노드로, 왼쪽(공급값처럼 신원을 알 수 없으면)은 Non-component 노드로 그래프가 이미 담한다.
5. **동일 술어 이형 표기** — 같은 참거짓의 다른 표기(구문 변형, `x != null` ↔ `x !== null && x !== undefined`, `list.length` ↔ `list.length > 0`). 하나의 controlId로 접는다. 구현 범위: 접기 판정을 라벨 텍스트에서 AST 구조 키로 바꾼다 — 공백·괄호·문자열 인용부호 변형이 공짜로 통합된다. 네이티브 true/false 분기(양팔 렌더 삼항·if)도 같은 접기에 편입한다 — 같은 불린 주제의 분기 2벌은 각자 스위치가 되어 어긋날 수 있어(463b132와 같은 부류, rdtc `selectAll?.hideSelectAll` 실측) 반드시 하나로 접혀야 한다. 홀로인 분기는 true/false 값 공간을 그대로 유지한다. truthiness 동등성 등 타입 판단이 필요한 등가는 타입 판단 비용 때문에 여전히 후순위(0001 유지).
6. **겹치는 값 공간** — 순서형 비교·범위(`n > 0` / `n > 1`). 케이스는 상호배타여야 하는데 이류는 서로 포함된다. 같은 임계값의 상보쌍(`> 0`/`<= 0`)은 겹치지 않는 2값 주제라 스위치로 통일했다 — 이류는 다른 임계값끼리 겹치는 경우만 남는다(그룹 키가 리터럴까지 포함해 서로 다른 컨트롤로 존재). 등식 병합과 달리 구간 분할 의미론이 필요해 별도 설계로 남긴다. 검토 방향(미구현): 같은 주제의 임계값을 모아 값 공간을 순서 구간으로 쪼개 케이스로 두고(예: `≤ 0`/`= 1`/`≥ 2`) 원 게이트를 구간 집합으로 번역한다 — 다값 전개·나머지 합성 기계는 판별식이 이미 갖추고 있다. 비리터럴 우항, 비숫자 도메인, 임계값 과다, 규칙 곱 폭발은 전부 그 주제만 현행(분리 컨트롤)으로 되돌리는 폴백으로 처리한다.

변환 불가 인지만 하는 한계: 같은 텍스트여도 시점마다 참거짓이 다른 식(가변 로컬). 컨트롤 신원이 텍스트 기반인 이상 해소되지 않는다.

## 원칙

- 변환은 생성기에서 1회. 클라이언트는 받은 컨트롤을 그대로 쓴다. 라벨 파싱·극성 추론의 클라이언트 이관 금지.
- 1+2+3(병합·합성·양형 정규화)이 한 세트로 함께 간다.
- 결정 체인은 소스 순서를 따른다 — 외부 게이트가 먼저 온다. 규칙 배열의 요구 순서가 그 순서를 암묵적으로 실으므로, 재작성(판별식 병합·나머지 합성)은 각 판별식 그룹을 첫 요구의 슬롯에서 해소해야 한다. 해석 결과를 규칙 끝에 붙이면 체인이 뒤집히고, 후행 게이트의 dependsOn(선행 게이트의 통과 조건)이 역방향 체인에서 도달 불능이 되어 그 아래 그래프 전체가 소등한다. 실측: workspace-page의 `if(state.status…)` 이후 `if(!state.review.catalog)` — catalog가 바깥 분기로 투영돼 loading/error 선택 시 경로가 죽었다.
- 극성쌍의 케이스 순서는 양형 우선 — 스위치의 켜짐 슬롯(cases[0])은 필드 라벨이 밝히는 조건과 일치해야 한다. `if(!x)`로 작성된 게이트도 양형 케이스가 앞선다. 케이스 id는 의미 그대로 유지한다(true = 게이트 표기대로 참).

## ADR 0001 대비 변경

- "케이스 ID와 라벨은 해당 극성 표현식 그대로" 폐기 → 주어/비교값 유도.
- "복합식 미분해 유지" → 순수 결합·분리의 분해로 전환. ADR 0002의 이월 과제 '복합식 미분해 완화'를 흡수한다.
- 드모르건 전개 "후순위" → 3류 정규화로 채택. 의미 보존이라 안전하다는 0001의 판단은 그대로다.
- 유지: Rule 등가 정규화 기각(간선 수의 구조 사실 왜곡), truthiness 동등성 후순위.
- ADR 0002의 이월 과제 '표현식 정규화'는 5류로 흡수한다.
- 케이스 라벨의 따옴표 제거(43d8935) 반전 → 리터럴 표기 유지. 타입 구분(`"1"` ↔ `1`)이 제거로 얻는 절약보다 크다.

## 검증

1~5류는 개밥먹기 실측 사례 전부를 흡수한다 — 1: `state.status`·`conflict?.kind` 판별식 쌍, 2: 암묵 else 유래 `!(X)` 케이스, 3: `!(!data)`·`!(!first || !last)`·`!(links.length === 0)`, 4: `A && B` 통짜 게이트, 호출식 원자, 그리고 렌더 팔이 하나뿐인 4항 분리(`data.eyebrow != null || …`), 5: `data.links?.length` 진위형과 rdtc `selectAll?.hideSelectAll` 삼항 2벌 접기. 쇼케이스(react-data-table-component, react-admin demo)도 같은 생성기로 재생성해 검증한다. 결정 체인 소스 순서도 실측으로 고정한다 — status→catalog 체인에서 loading/error 클릭 시 반환 경로가 점등하고 나머지 팔은 1개로 병합된다. 6류와 가변 로컬 한계는 실측에 없다 — 논리적 추가다.

## Consequences

- 동일 판별식 체인이 하나의 결정 노드(케이스 N개)로 합쳐지므로 배타가 구조로 보장되고, 463b132류의 사후 정산은 이류 결함에 대한 임시 방편으로 남는다.
- 케이스 라벨이 원문이 아니라 유도값이 되므로, 원문 식 확인이 필요한 곳(소스 추적)은 별도 경로로 제공해야 한다.
- 복합식 분해는 규칙 수·간선 수를 늘릴 수 있다. 기각된 Rule 등가 정규화(사실 축소)와 달리 분해는 게이트 N벌이라는 구조 사실을 보존하는 방향이다.
- 실 구현 시 생성기(react-component-structure 분석기)와 아티팩트 스키마(케이스 라벨 유도·여집합 케이스) 양쪽 작업이 생긴다. 스파이크 범위 확장을 수용한다.
