# 컴포넌트 구조 다이어그램: 분기/조건부 컨트롤의 판정 기준과 간선 동작

컴포넌트 구조 다이어그램은 렌더링 경로의 조건을 "하나의 상태 변수 = 하나의 컨트롤" 원칙으로 모델링한다. 게이트 표현식을 소스에 등장한 대로 컨트롤로 옮기면 같은 변수를 검사하는 조건들이 서로 독립된 플래그가 되어, 실제로는 동시에 성립할 수 없는 상태(예: `shouldShow=on`과 `!shouldShow=on`)가 선택 가능해진다. 이는 소스 충실이 아니라 컨트롤 모델의 왜곡이므로, 수집 단계에서 배타성을 복원하고 간선은 구조 사실을 그대로 드러내기로 했다.

## 분기와 조건부의 판정 기준

- 분기(branch): 같은 소유자 안에서 하나의 피연산자에 대해 상호배타적인 값 둘 이상이 관측될 때. 원천은 세 가지다.
  1. 소스의 제어 흐름 자체가 분기인 경우 — 삼항(`true`/`false`), `if` 양분기(`true`/`false`), `switch`(`case:N` + 필요시 `default`), `||`·`??` 대안(`left`/`right`).
  2. 흩어진 조건부 게이트의 극성 통합 — 재귀적 `!` 스트립(`!!X` 포함)으로 같은 피연산자의 `X`/`!X` 쌍을 인식.
  3. 비교·열거 짝 — 동일 피연산자 쌍의 반전 연산자(`>`↔`<=`, `>=`↔`<`, `===`↔`!==`, `==`↔`!=`), 같은 변수의 `===` 리터런 모음(값마다 케이스). `!==`·`!=`는 상보 짝이 관측된 이진 상황에서만 케이스로 매핑된다.
- 조건부(conditional): 위의 짝이 관측되지 않고 단일 값만 남을 때. 값 공간은 `on`/`off`이고, 같은 표현식의 중복 게이트 인스턴스는 하나의 컨트롤로 접힌다.
- 기계적 기본값: 케이스 순서는 소스 등장 순, 케이스 ID와 라벨은 해당 극성 표현식 그대로, 컨트롤 라벨은 양극성(부정 아닌) 케이스의 표현식.
- `A && B`와 `B && A`가 다른 지점에서 관측되면 접힌 컨트롤들이 서로의 선행 조건이 되어 순환이 생긴다. 순서가 다른 게이트의 피연산자는 선행 조건이 아니라 피어이므로, 소스 순서상 나중 컨트롤이 순환을 닫는 요구를 버린다.

## 간선의 표현과 동작

- 분기 컨트롤은 결정 노드로 투영되고 각 케이스가 포트가 되어 팔마다 간선이 나뉜다. 조건부는 노드를 갖지 않고, 제약하는 홉의 간선 라벨 가드로 렌더된다.
- 경로 요구 규칙(Rule)이 분기 사슬을 건너면 절(segment)로 잘리는데, 같은 (소스, 타깃, 포트)인 절만 하나의 간선으로 합쳐진다(Union). 극성이 다르면 포트가 달라 팔이 갈라진 채 남는다 — 이는 의도된 표현이지 중복이 아니다.
- 어떤 렌더링 경로도 요구하지 않는 케이스는 죽은 팔(Dead Arm)로 자체 Non-component 노드에 닿는다. 아무것도 렌더하지 않음도 하나의 렌더링 경로이므로 선택 가능하게 유지한다.
- 간선 강조는 Ruleset 중 하나의 Rule이 현재 선택에 충족될 때만 켠다(값 만족과 간선 활성을 구분한다). 간선이 참조하는 조건부를 모두 끄면 모든 Rule이 미충족이 되고, 간선과 하위 전체가 흐려진다.
- 클릭 상호작용: 미충족 조건 pill을 클릭하면 해당 경로 요구가 현재 선택에 적용되며 경로가 다시 라우팅된다. 충족 상태의 절을 클릭하면 절 단위로 해제되는데, 해제 대상은 "클릭 시점에 다른 활성 Rule이 공유하지 않는 조건부"로 한정하는 온건한 배타를 쓴다(공유 중이면 해제하지 않고, 배타 대상이 없으면 절 전체를 끈다). 분기 케이스는 항상 한 케이스를 유지하므로 해제 대상에서 제외된다.

## Considered Options

- **Rule 등가 정규화 — 기각.** `[A,X]∨[A,!X]→[A]` 같은 극성쌍 병합이나 `[A]∨[A,B]→[A]` 흡수는 진리표를 같게 유지하지만, 게이트가 N벌 존재한다는 구조 사실을 지운다. 간선 수와 Rule 수의 일치는 "사실 왜곡이 없다"와 동의어가 아니며, 분기의 여러 Rule이 하나의 간선에 실리는 것(구조 사실 그대로)과 대비된다. 정규화는 컨트롤(상태 변수)에만 적용한다.
- **표현식 정규화 확장 — 후순위.** 드모르간 전개(`!(A||B)` ≡ `!A && !B`)는 의미를 보존하므로 안전하지만, `X === true` ≢ `X` 같은 truthiness 동등성은 타입 판단이 필요해 비용이 커서 아직 하지 않는다. 같은 이유로 복합식(`X || Y`를 하나의 피연산자로 취급)의 미분해도 유지한다.

## Consequences

- 동일한 컴포넌트를 렌더하는 상호배타 게이트는 "하나의 간선에 모순된 가드" 대신 "결정 노드의 팔 두 개"로 표시된다. 라벨 중복이 사라지고 불가능 상태가 사라진다.
- 서로 다른 조건 조합의 정당한 OR, 같은 케이스 안의 조건 조합, 중첩 게이트, 복합식 미분해, 구문 변형은 간선에 Rule 여러 개로 그대로 남는다. 이 나열은 왜곡이 아니라 각각의 게이트를 조건부로 표현한 구조 사실이다.
