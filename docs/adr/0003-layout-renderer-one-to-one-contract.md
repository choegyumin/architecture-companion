# 레이아웃과 렌더러의 1:1 계약 — 렌더러 선택은 레이아웃 기준으로

렌더러의 실제 의존는 그래프 종류가 아니라 레이아웃이 생산하는 지오메트리 계약이다.
`elk-layered-diagram-layout`은 ELK 좌표 위에 도메인 지오메트리(결정 노드 4×4 포트, 꼭짓점 배분,
역방향 앵커, 세그먼트 분할)를 얹으며, 컴포넌트 구조 렌더러는 이 계약을 소비해 그린다.
그런데 현재 렌더러 선택은 그래프 종류 기준으로 분기하므로 결합이 암묵적이다 —
컴포넌트 구조에 다른 레이아웃 id를 주면 렌더러가 기대하는 지오메트리가 사라지고,
elk-layered를 다른 그래프에 적용하면 그 렌더러가 지오메트리를 해석하지 못한다.

## 결정

실 구현에서 렌더러 선택을 그래프 종류 축에서 레이아웃(`layout.id`) 축으로 이관하고,
레이아웃과 렌더러는 1:1로 대응시킨다. 레이아웃이 정의한 지오메트리 계약을 정확히 그 렌더러만 소비한다.
그래프 종류 차이(컴포넌트 구조의 필드 UI, hover 팝오버 등)는 렌더러 내부 확장이나 위젯 주입으로 표현한다.
생성기와 레이아웃은 1:N을 허용한다 — 레이아웃은 좌표 계산이므로 그래프 내용과 독립적으로 재사용될 수 있고,
아티팩트가 `layout.id`로 선택한다.

현재 진행 중인 스파이크(`spike/owner-controls-and-route-inference`)에서는 이 매핑을 정비하지 않고
기존 선택 구조 위에서 실험한다. 스파이크 산출물을 실 구현으로 옮길 때 이 요구사항을 적용한다.
