# 간선 호버 점등 — CSS와 상태 채널의 분업

라벨에 호버하면 그 간선도 밝아져야 한다. 그런데 간선 호버 효과는 간선 요소의 CSS `:hover`(opacity 0.55→1)로만 존재했고,
라벨은 `EdgeLabelRenderer`(간선 SVG와 형제 레이어)에 살아서 DOM 구조상 자기 간선을 가리킬 방법이 없다. CSS `:has()`로도 도달 불가.

## 결정

효과를 두 경로로 분업한다.

- **자기 자신 효과는 CSS 그대로**: 간선 `:hover`, 라벨·노드 `hover:border-primary/60`. 포인터가 자기 위에 있다는 사실은 브라우저가 무료로 주고 재렌더가 없다. 상태로 옮기면 같은 효과에 이벤트→상태→재렌더 왕복만 얻는다.
- **자기가 아닌 것을 밝힐 때만 상태 채널**: 라벨은 호버 주체(origin — `edge` | `label` | `node`)를 모듈 수준 채널(`shared/react-flow/edge-hover.ts`)로 보고하고, 캔버스가 주체를 간선 집합으로 해석해 해당 간선에 `is-edge-hovered` 클래스를 스탬프한다. CSS는 `:hover`와 그 클래스를 같이 받는다.

해석 규칙:

- 기본: 주체가 간선/라벨이면 그 간선 1개. 노드는 빈 집합(기본 무효과 — 노드 호버 점등은 덮어쓰기 전용 기능).
- 덮어쓰기: 렌더러가 캔버스에 `resolveEdgeHover(origin) → 간선 집합`을 줄 수 있다. 상태를 소유한 노드부터 호버 주체까지 경로 전체를 밝히는 식의 커스텀은 여기에 낀다. 라벨·노드 점등은 렌더러가 같은 함수로 계산해 자기 emphasis에 재사용한다(순수 함수라 두 호출이 어긋나지 않는다).

## 왜 React Context가 아니라 모듈 채널인가

라벨을 만드는 것은 다이어그램 렌더러고, 렌더러는 캔버스 컴포넌트의 위에서 실행된다. Provider를 캔버스 안에 두면
Provider 밖인 렌더러가 채널을 못 본다. 모듈 수준 채널은 방향 없이 누구나 보고·구독한다.

- 해제는 "나중 호버 승리": leave 보고는 채널이 든 주체와 같을 때만 지운다.
- 캔버스 언마운트 시 채널을 리셋한다 — 사라진 라벨(탭 전환 등, leave 이벤트 없이 제거)이 다음 다이어그램의 간선을 켜는 것을 막는다.
- 단일 채널이므로 한 페이지에 캔버스가 여러 개면 주체를 공유한다. 현재 워크스페이스는 항상 캔버스 1개.

## 귀결

- 노드 호버 보고는 스키마(`kind: "node"`)만 확보했다. 실제 배선은 덮어쓰기가 필요해질 때 — `card-node`의 `onHoverChange`가 그 통로가 된다(폐지 보류).
- 실측(4317, 개밥먹기): 라벨 호버 → 간선 1개 점등(opacity 1, 비점등 0.55) + 우측 하단 diff 카드, 다른 라벨로 이동 → 주체 교체, 라벨 밖으로 이동 → 소등·카드 소멸.
