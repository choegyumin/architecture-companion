# 간선 라벨 조건 표기 폐지 — 소유 노드 필드와 경로 역산 상호작용으로 전환

간선 위에 떠다니는 pill 라벨로 분기 케이스와 조건부 requirement를 표시하던 방식을 폐지한다.
반복된 문제(라벨 배치 충돌, 동일 표현식의 간선 간 중복, 다중 requirement 상호작용의 복잡성, 조건식의 소유 컴포넌트가 다이어그램에 드러나지 않음)의 공통 근원이
"조건을 공간을 점유하는 개별 클릭 물체로 간선 위에 뿌린다"는 표현 재료 선택이었기 때문이다.
새 모델은 표현과 조작을 분리한다: 조건의 표시·직접 조작은 소유 노드의 필드가 담당하고(필드를 담은 결정 노드를 소유 카드 아래에 두는 형태,
카드 내장 여부 등 디자인은 스파이크로 검토), 자손 노드 hover는 "이 경로가 켜지려면 어떤 옵션이 어떻게 바뀌어야 하는가"를 before/after diff로 보여주며,
클릭은 그 diff를 역산 적용한다(기존 `applyClause` 엔진 재사용). 간선은 활성/비활성 색만 남는다.

## 폐지되는 남은 작업

기존 안에 쌓인 보류 작업 중 다음은 전부 라벨에 의존하므로 라벨 폐지와 함께 폐지된다:

- 조건부 라벨 겹침 해결(collision 패스 간선 간 확장)
- 중첩 체크박스(AND 박스 삼태 표시) 재검토
- 인터랙션 피드백(직접 누른 pill과 자동 켜진 pill의 시각 구분)
- 트렁크(같은 케이스 간선군의 단일선 분기)
- pill 라벨 가공(코드 표현식 → 사람 라벨)

모델과 무관한 작업은 이월된다: 표현식 정규화(드모르건 등), 복합식 미분해 완화, 초기 뷰 활성 경로 포커스.

## 스파이크 확정 (spike/owner-controls-and-route-inference)

- 간선 라벨의 최종 처우는 "경로당 조합식 1회"로 확정했다: 간선마다 전체 활성 조건을 하나의 버튼 라벨로 싣는다(최대 폭 제한+줄바꿈). pill·AND 박스·상태 아이콘 press 같은 라벨 의존 재료는 폐지 유지.
- 조작은 라벨 클릭이 경로 전체 규칙을 적용하는 방식으로 환원 — 소유자 필드와 같은 엔진(`selectEdgePath`)을 쓴다.
- 라벨 배치 코드(collision, 앵커 방향, push-off)는 제거 대상이 아니라 조합식 라벨의 배치기로 재접속했다. 배치는 쌍별 밀기/당김의 라운드 반복이 아니라 **한 번의 전역 결정**이다: 각 라벨은 자기 간선 위 이산 슬롯(4px) 중 하나를 고르고, 겹침 면적(노드는 100배, 같은 해력도의 슬롯 간에는 기본 오프셋 근처 선호)을 비용으로 그리디가 최악 충돌 라벨부터 낮춘다. 혼합 쌍의 팔-아래 역전은 두 라벨이 같은 기둥으로 읽히는 밴드에서만 과금한다(x 범위 접촉 + 세로 간격이 두 박스 높이 합 이내). 초판은 y거리 무제한으로 과금해 라벨이 수백 px 아래의 쌍을 회피하려고 간선 끝까지 비행했다(실측 최대 +368px). 순수 y교차 게이트는 접선(0px) 역전을 공짜로 만들어 만남-쌍 테스트가 적발했다 — 밴드 폭을 박스 높이 합으로 정한 근거다. 라운드 방식이 실패한 이유: 2차원 배치를 1차원 offset으로, 전역 배치를 쌍별 국소 힘으로 풀어 평형점 없는 진동(±18 왕복 실측)과 평행 팔 불분리가 남았다. 전역 결정은 반복이 없어 진동이 구조적으로 불가능하다(실측: 33개 라벨 겹침 0, 혼합 순서 유지). 그리디는 국소 탐색이라 최적임을 보장하지 않는다 — 잔여 겹침이 생기면 수용한다.
- 라벨 호버의 before/after diff 카드는 뷰포트 우측 하단에 고정한다(줌·팬을 따라다니지 않는다). 우측 하단은 앞으로 모든 정보 표현의 표준 위치다. diff 항목은 소유 컴포넌트명으로 그룹지어 표기한다.
- 노드 hover는 diff를 내보지 않는다(확정 변경: 초안의 "자손 노드 hover가 diff를 보여준다"는 철회). 노드는 자기 진입 간선을 정확히 지목하지 못해 diff의 주어가 모호해지고, 간선 노드를 다시 만들어 캔버스가 흔들리는 부작용만 있었다. diff는 정확한 규칙을 이름 걸고 있는 간선 라벨 호버가 유일한 출구다.

## Considered Options

- **라벨 배치 개선 지속**(꼭짓점 배분·역방향 앵커·세로 스택·방향 성장) — 각각 실측 개선은 있었으나 문제의 근원(떠다니는 텍스트 물체)을 없애지 못했다.
- **색 인코딩**(케이스별 색견본+색점) — 배치·중복은 해결하나 식 판독이 범례 왕복의 간접 참조가 된다.
- **노드 안 옵션 단순 복귀**(경로 미표시) — 조작은 단순하나 "어떤 조건이 어떤 경로를 켜는지"가 다이어그램에서 사라진다.
- **간선별 전체 조건식 조합 라벨** — 간선의 조건 완결성은 확보하나 라벨 의존 작업들이 부활한다. hover 콘텐츠(조합식+diff)로 쓰는 것만 채택.
- **같은 결정의 팔 라벨 케이스 순서 정렬(계단식)** — Big-M 벌점으로 구현했으나 벌점 위계가 다른 비용을 무의미화해 노드 스침·완전 겹침 부작용을 낳았고 전면 폐기. 순서는 취향 문제로 기각.

## Consequences

- 정적 판독의 대가: 간선만 보고서는 활성 조건을 알 수 없다. 조건 확인은 소유자 필드(현재값) 또는 hover(diff)를 거친다.
- 의존 체인(결정 노드 간 간선, 예: `isBusy→hasData→progress`)의 시각화가 소실된다. 전제 조건은 간선 활성 규칙(activeWhen) 데이터에는 보존되며 hover diff로만 노출된다.
- 간선 라벨의 최종 처우(완전 제거 vs 최대 폭 제한+줄바꿈 조합식 1회)는 스파이크(`spike/owner-controls-and-route-inference`)에서 DOM 실측으로 결정한다.
- 라벨 배치 코드(collision, 앵커 방향, push-off)는 새 안 확정 시 제거 대상이다.
